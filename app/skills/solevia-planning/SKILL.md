# Solevia planning

先复述目标和硬约束，再按依赖顺序拆解任务。每个任务包含名称、预计时长或容量、前置依赖和验收条件。日期、容量或依赖不确定时保留不确定性并提出澄清，不得为了得到完整表格而补造数值。

当前业务节点的 Schema 决定实际输出，普通对话中的复述不能混入机器字段。生成前核对：

- 起止日期、时区、硬截止日期和可执行日范围；星期编号使用上下文约定，通常周一为 0。
- 任务单次时长、次数与总时长必须一致；每日和每周工作量不得超过对应时段容量，例外日不按普通日扩容。
- 阶段必须完整覆盖路线，阶段数与实际可执行天数相容；两天窗口不能伪造三天或忽略阶段覆盖。无法同时满足时返回约束冲突，请求用户决定，不偷偷修改日期。
- 每个必做工作项及其次数都有承接，不能以空日历、占位任务、只排第一周或删除高难度任务代替完整计划。
- 数量承诺的单位必须可计数。要求 N 个可验收产出时，为每个完整产出安排独立验收动作并绑定原 commitment label，设置稳定且全计划唯一的 occurrence_key（如 TEST.01、TEST.02）。同一产出的准备、实施、复核沿用同一身份，只有完整验收动作兑现一次；描述里写“完成8个”不能让一个动作自动算8次，也不能把准备与验收重复计数。保持真实容量，不通过增加工作日满足数量。
- OUTCOME 的 D1 是整周成果窗口，不是只允许投入一天；按每周总容量设计窗口，再由执行层分配到实际可用日。每次60分钟限制每次工作时段，不能把每周4次各60分钟误缩为整周只60分钟。
- 依赖键引用已有注册项或本批合法新项，不自引用、不循环；候选组成员声明与 group_key 一致。前置项不可排在后置项之后。
- 已开始、已完成及冻结任务按给定调整范围处理；建议不等于已应用，不覆盖用户已确认版本。

修复时区分结构错误与业务冲突。格式或唯一可确定的引用错误可按反馈修正；工作量/容量/日期/目标覆盖冲突需要重新设计或澄清，不通过机械填默认值掩盖。任何确定性降级方案也必须经过同样的校验。
